01

El reto

Desarrollarás un sitio web de temática libre, utilizando los conocimientos de HTML y CSS que hemos trabajado durante el curso.

Podrás elegir cualquier temática que te interese: un videojuego, una película, una banda musical, un negocio, una tienda, una institución, un portafolio personal, una comunidad, un proyecto ficticio o cualquier otra idea que quieras convertir en un sitio web.

El objetivo: construir un sitio web que tenga identidad propia, contenido organizado, navegación entre páginas, diseño visual personalizado y que pueda consultarse públicamente desde Internet.

No se trata de hacer tres páginas independientes sin relación entre ellas. Las tres deberán formar parte de un mismo proyecto y mantener una identidad visual coherente.

02

Requisitos del sitio

📄 A. Estructura y contenido

  • El sitio deberá contar con un mínimo de 3 páginas HTML independientes.
  • La página principal deberá llamarse obligatoriamente index.html.
  • Las páginas deberán estar relacionadas con una misma temática.
  • Implementar un menú o sistema de navegación para desplazarse entre ellas.
  • Mantener una identidad visual consistente en todas las páginas.
  • Incluir contenido real y organizado, no únicamente elementos decorativos.
  • Utilizar imágenes y otros recursos multimedia cuando sean pertinentes.

Ejemplo de distribución:

Página 1

Inicio: presentación del proyecto, introducción y contenido destacado.

Página 2

Contenido: información, catálogo, galería, productos o servicios.

Página 3

Complementaria: contacto, información adicional, formulario o comunidad.

🏗️ B. Organización obligatoria de carpetas

Todos los proyectos deberán respetar una estructura organizada de archivos y directorios. No se aceptarán proyectos que tengan todos sus archivos mezclados en una sola carpeta.

MiSitioWeb/ │ ├── index.html # Página principal (obligatoria) ├── nosotros.html # Segunda página ├── contacto.html # Tercera página │ ├── CSS/ │ └── styles.css # Hojas de estilos │ ├── JS/ │ └── script.js # Scripts (si se implementan) │ └── assets/ │ ├── img/ # Imágenes ├── audio/ # Archivos de audio └── video/ # Archivos de video

¡Ojo! El archivo index.html debe permanecer en la raíz del repositorio, no dentro de otra carpeta. Las carpetas CSS, JS y assets también deberán estar en ese mismo nivel.

Las tres páginas HTML deberán permanecer en la raíz. Los archivos CSS se guardarán dentro de CSS, los scripts dentro de JS y los recursos multimedia dentro de su correspondiente subcarpeta de assets.

También deberás utilizar rutas relativas correctas para conectar tus páginas con los estilos, scripts e imágenes.

# Ejemplos de rutas desde index.html <link rel="stylesheet" href="CSS/styles.css"> <script src="JS/script.js"></script> <img src="assets/img/imagen.jpg" alt="Descripción"> # Navegación entre páginas <a href="nosotros.html">Nosotros</a>

04

Implementación de CSS

El diseño visual deberá realizarse mediante una hoja de estilos CSS propia, vinculada correctamente a las páginas HTML.

Propiedades y recursos revisados

background bgcolor color text-align
margin padding border-radius width height
display: flex :hover class id

Tipografía con Google Fonts

También deberás personalizar la tipografía de tu sitio web utilizando fuentes externas de Google Fonts, integradas mediante CSS o mediante el enlace correspondiente en HTML.

La elección de fuentes deberá ser coherente con la identidad visual del proyecto. No basta con cambiar la fuente: debes saber explicar cómo la importaste y cómo la aplicaste a los elementos de tu página.

Diseño personalizado

  • Utilizar una paleta de colores definida.
  • Establecer jerarquías visuales mediante tamaños y estilos de texto.
  • Aplicar márgenes y rellenos para organizar los elementos.
  • Diseñar menús, botones y secciones con estilos propios.
  • Utilizar Flexbox para distribuir elementos cuando sea conveniente.
  • Incorporar efectos visuales e interacciones mediante pseudoclases como :hover.

El diseño importa: no se aceptará un sitio que conserve únicamente la apariencia predeterminada del navegador. Deberás demostrar que puedes controlar la presentación visual mediante CSS.

05

Investigación y conocimientos adicionales

¡Aquí puedes lucirte! Se permite investigar e implementar propiedades, etiquetas, técnicas o recursos que no hayamos revisado directamente en clase.

Algunos ejemplos de elementos que podrías investigar:

HTML

  • Etiquetas semánticas adicionales.
  • Audio y video.
  • Formularios más elaborados.
  • Otros atributos HTML.

CSS

  • Animaciones y transiciones.
  • Grid Layout.
  • Sombras y gradientes.
  • Diseño responsivo.
  • Variables CSS.

La regla es sencilla: todo lo adicional que implementes y puedas explicar o justificar será tomado en cuenta como mérito adicional. Sin embargo, no se otorgará valor adicional por copiar código avanzado que no puedas explicar.

Si incorporas una técnica nueva, deberás poder responder:

  1. ¿Qué hace?
  2. ¿Cómo funciona?
  3. ¿Por qué decidiste utilizarla?
  4. ¿En qué parte de tu proyecto la implementaste?
06

Publicación en GitHub Pages

Tu proyecto deberá estar disponible públicamente en Internet mediante GitHub Pages.

Requisitos de publicación

  1. Crear un repositorio en GitHub para el proyecto.
  2. Subir todos los archivos y carpetas respetando la estructura solicitada.
  3. Verificar que el archivo index.html se encuentre en la raíz.
  4. Configurar GitHub Pages desde la sección Settings del repositorio.
  5. Seleccionar la rama y carpeta de publicación correspondientes.
  6. Comprobar que el sitio se encuentre publicado correctamente.
  7. Verificar que las tres páginas funcionen desde la versión publicada.

¡Atención! No basta con que el repositorio exista o que el código esté subido. El sitio deberá estar publicado y funcionar correctamente desde su enlace de GitHub Pages.

Comprueba especialmente:

  • Que los enlaces entre páginas funcionen.
  • Que las imágenes y recursos multimedia carguen.
  • Que los estilos CSS se apliquen correctamente.
  • Que las rutas funcionen en GitHub Pages.
  • Que no existan errores evidentes de navegación o visualización.
07

Entregables

La entrega deberá contener los siguientes elementos:

📦 1. Repositorio de GitHub

Enlace público al repositorio que contiene todos los archivos del proyecto.

🌍 2. Sitio web publicado

Enlace directo a tu sitio funcionando mediante GitHub Pages.

📸 3. Evidencia del funcionamiento

Capturas de pantalla de las tres páginas del sitio web ya publicadas.

📝 4. Explicación técnica

Un documento breve que incluya:

  • Nombre y temática del proyecto.
  • Propósito y descripción del sitio.
  • Función de cada una de las tres páginas.
  • Etiquetas HTML más importantes que utilizaste.
  • Propiedades CSS que implementaste.
  • Fuentes de Google Fonts utilizadas y cómo las integraste.
  • Elementos adicionales investigados y explicación de su funcionamiento.

🧠 5. Defensa técnica individual

Deberás estar preparado para explicar el funcionamiento de tu proyecto y responder preguntas sobre el código que desarrollaste.

08

Criterios de evaluación

El proyecto será evaluado considerando tanto su calidad técnica como el resultado visual y el dominio de los conocimientos implementados.

Criterio Valor
Estructura y organización de las tres páginas HTML. 20%
Implementación y uso adecuado de HTML. 20%
Diseño visual e implementación de CSS. 25%
Navegación, enlaces y funcionamiento del sitio. 10%
Publicación y funcionamiento en GitHub Pages. 10%
Explicación técnica y dominio del código. 15%
TOTAL 100%

Sobre los elementos adicionales: la investigación, implementación y explicación de recursos que no se revisaron en clase podrán considerarse como mérito adicional dentro de la valoración del proyecto. Su incorporación no sustituye ninguno de los requisitos obligatorios.

09

Consideraciones finales

  • El proyecto deberá ser de autoría propia.
  • Se permite consultar documentación y tutoriales.
  • Se permite utilizar inteligencia artificial como herramienta de apoyo.
  • Todo código implementado deberá poder ser explicado por el estudiante.
  • No se aceptarán proyectos con páginas incompletas o enlaces rotos.
  • La estructura de carpetas deberá respetarse.
  • El repositorio y el sitio publicado deberán ser accesibles.
  • Se evaluará tanto el resultado como el proceso y los conocimientos demostrados.
